# GW-004: Rate Limit

## User Story
> As a Gateway, I enforce rate limits per role so that the API is protected from abuse and ensures fair usage.

## API

### Rate Limits by Role

| Role | Limit | Window |
|------|-------|--------|
| GUEST | 100 requests | per minute |
| BUYER | 500 requests | per minute |
| SELLER | 1000 requests | per minute |
| ADMIN | unlimited | - |

### Rate Limit Headers

**Response Headers:**
```http
X-RateLimit-Limit: 500
X-RateLimit-Remaining: 450
X-RateLimit-Reset: 1712086500
```

### Rate Limited Response (429)

```json
{
  "error": "RATE_LIMITED",
  "msg": "Too many requests",
  "retryAfter": 60
}
```

### Example Scenarios

**GUEST Request:**
```http
GET /api/v1/products HTTP/1.1
Host: gateway:8091
```

**Response Headers (first request):**
```http
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 99
X-RateLimit-Reset: 1712086500
```

**When Exceeded (429):**
```http
HTTP/1.1 429 Too Many Requests
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1712086560
Content-Type: application/json

{
  "error": "RATE_LIMITED",
  "msg": "Too many requests",
  "retryAfter": 60
}
```

**ADMIN Request:**
```http
GET /api/v1/users HTTP/1.1
Host: gateway:8091
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Response (no rate limit headers):**
```http
HTTP/1.1 200 OK
X-User-Id: admin-001
X-User-Role: ADMIN
```

---

## Acceptance Criteria

- [ ] GUEST role limited to 100 requests per minute
- [ ] BUYER role limited to 500 requests per minute
- [ ] SELLER role limited to 1000 requests per minute
- [ ] ADMIN role has unlimited requests
- [ ] Returns 429 with retryAfter when limit exceeded
- [ ] Includes X-RateLimit-* headers in all responses
- [ ] Rate limit counter resets after the window expires
