# GW-006: Error Response

## User Story
> As a Gateway, I return proper error format for common error codes so that clients can handle errors consistently.

## API

### Error Response Format

All error responses follow a consistent JSON structure:

```json
{
  "error": "ERROR_CODE",
  "msg": "Human-readable msg",
  "timestamp": "2026-04-04T10:30:00Z",
  "path": "/api/v1/resource"
}
```

### Error Codes and Responses

#### 401 Unauthorized

```http
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{
  "error": "UNAUTHORIZED",
  "msg": "Invalid or expired token",
  "timestamp": "2026-04-04T10:30:00Z",
  "path": "/api/v1/orders"
}
```

**Scenarios:**
- Missing Authorization header
- Invalid JWT signature
- Expired JWT token
- Malformed token

#### 403 Forbidden

```http
HTTP/1.1 403 Forbidden
Content-Type: application/json

{
  "error": "FORBIDDEN",
  "msg": "Insufficient permissions",
  "timestamp": "2026-04-04T10:30:00Z",
  "path": "/api/v1/seller/products"
}
```

**Scenarios:**
- User lacks required role (e.g., BUYER accessing /api/v1/seller/**)

#### 404 Not Found

```http
HTTP/1.1 404 Not Found
Content-Type: application/json

{
  "error": "NOT_FOUND",
  "msg": "Endpoint not found",
  "timestamp": "2026-04-04T10:30:00Z",
  "path": "/api/v1/unknown"
}
```

**Scenarios:**
- No route matches the request path

#### 429 Too Many Requests

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 60

{
  "error": "RATE_LIMITED",
  "msg": "Too many requests",
  "retryAfter": 60,
  "timestamp": "2026-04-04T10:30:00Z",
  "path": "/api/v1/products"
}
```

**Scenarios:**
- Rate limit exceeded for user role

#### 500 Internal Server Error

```http
HTTP/1.1 500 Internal Server Error
Content-Type: application/json

{
  "error": "INTERNAL_ERROR",
  "msg": "Service temporarily unavailable",
  "timestamp": "2026-04-04T10:30:00Z",
  "path": "/api/v1/orders"
}
```

**Scenarios:**
- Unexpected error in gateway processing
- Downstream service returned unexpected error

#### 503 Service Unavailable

```http
HTTP/1.1 503 Service Unavailable
Content-Type: application/json
Retry-After: 30

{
  "error": "SERVICE_UNAVAILABLE",
  "msg": "Service temporarily unavailable",
  "service": "product-service",
  "retryAfter": 30,
  "timestamp": "2026-04-04T10:30:00Z",
  "path": "/api/v1/products"
}
```

**Scenarios:**
- Circuit breaker is open
- Downstream service is down

---

## Acceptance Criteria

- [ ] Returns 401 for missing/invalid/expired JWT
- [ ] Returns 403 for insufficient permissions
- [ ] Returns 404 for unmatched routes
- [ ] Returns 429 for rate limit exceeded with retryAfter
- [ ] Returns 500 for unexpected gateway errors
- [ ] Returns 503 when circuit breaker is open
- [ ] All error responses include error code, msg, timestamp, and path
- [ ] Error responses are valid JSON
