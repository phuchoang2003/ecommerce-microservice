# GW-021: Deregister Service

## User Story
> As a Gateway, I remove my registration from Consul on shutdown so that stale entries do not appear in service discovery.

## API

### Graceful Shutdown Flow

```
SIGTERM / SIGINT Received
        │
        ▼
┌──────────────────┐
│  Stop Accepting  │
│  New Requests    │
└──────────────────┘
        │
        ▼
┌──────────────────┐
│  Wait for Active │
│  Requests to End │
│  (timeout: 30s)  │
└──────────────────┘
        │
        ▼
┌──────────────────┐
│  Deregister from │
│  Consul          │
└──────────────────┘
        │
        ▼
┌──────────────────┐
│  Close Network  │
│  Connections     │
└──────────────────┘
        │
        ▼
        Process Exits
```

### Deregistration Details

| Field | Value |
|-------|-------|
| Service ID | gateway-{hostname}-{port} |
| Action | DELETE /agent/service/deregister/{serviceId} |

### Shutdown Sequence

**Phase 1: Stop accepting new requests**
```
[INFO] Gateway is stopping - no longer accepting new requests
```

**Phase 2: Wait for in-flight requests (max 30s)**
```
[INFO] Waiting for 5 active requests to complete...
[INFO] All active requests completed
```

**Phase 3: Deregister from Consul**
```
[INFO] Deregistering gateway from Consul: gateway-host-8091
[INFO] Gateway deregistered successfully
```

**Phase 4: Close connections**
```
[INFO] Closing network connections...
[INFO] Gateway shutdown complete
```

### Forced Shutdown (SIGKILL)

If the application does not terminate within the grace period:

```
[WARN] Graceful shutdown timed out after 30s
[WARN] Forcing shutdown...
```

### Application Properties

```yaml
spring:
  cloud:
    consul:
      discovery:
        deregister: true
        deregister-interval: 10s
        deregister-critical-service-on-error: true

server:
  shutdown: graceful

spring.lifecycle:
  timeout-per-shutdown-phase: 30s
```

---

## Acceptance Criteria

- [ ] Gateway deregisters from Consul on normal shutdown (SIGTERM)
- [ ] Gateway deregisters from Consul on interrupt (SIGINT)
- [ ] Gateway waits for in-flight requests to complete before deregistration
- [ ] Deregistration has a timeout (30s) after which forced shutdown occurs
- [ ] Deregistration fails gracefully if Consul is unreachable
- [ ] Log messages clearly indicate shutdown phases
- [ ] Service ID used for deregistration matches registration ID
- [ ] Consul UI shows service as "critical" then removed after deregistration
