# LOG-004: Webhook Receiver

## User Story
**As a** carrier system
**I want to** send tracking updates via webhooks
**So that** the platform can provide real-time tracking updates to customers

## API Endpoint
```
POST /api/v1/logistics/webhook
```

### Request Body (FedEx Format)
```json
{
  "carrier": "fedex",
  "eventType": "tracking_update",
  "trackingNumber": "794644790234",
  "timestamp": "2026-04-04T14:30:00Z",
  "status": "delivered",
  "statusCode": "DL",
  "statusDescription": "Package delivered",
  "location": {
    "city": "Beverly Hills",
    "state": "CA",
    "postalCode": "90210",
    "country": "US"
  },
  "signedBy": "JOHN DOE",
  "receivedAt": "2026-04-04T14:35:00Z"
}
```

### Request Body (UPS Format)
```json
{
  "carrier": "ups",
  "eventType": "tracking_update",
  "trackingNumber": "1Z999AA10123456784",
  "timestamp": "2026-04-04T14:30:00Z",
  "status": "in_transit",
  "statusCode": "I",
  "statusDescription": "In Transit",
  "location": {
    "city": "Phoenix",
    "state": "AZ",
    "postalCode": "85001",
    "country": "US"
  },
  "receivedAt": "2026-04-04T14:35:00Z"
}
```

### Response Body
```json
{
  "success": true,
  "msg": "Webhook received and processed",
  "webhookId": "wh_abc123def456"
}
```

## Acceptance Criteria
- [ ] Accept webhook payloads from multiple carriers
- [ ] Validate webhook signature/authenticity
- [ ] Parse carrier-specific payload formats
- [ ] Update tracking status in database
- [ ] Trigger notification events for status changes
- [ ] Return acknowledgment within 5 seconds
- [ ] Handle duplicate webhook events idempotently
- [ ] Log all incoming webhooks for auditing
